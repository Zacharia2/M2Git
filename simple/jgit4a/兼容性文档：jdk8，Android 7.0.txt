我已全面审查了 `Zacharia2/jgit4a` 项目的代码库。由于该项目目前配置为 JDK 11 且使用了大量 Java 9 至 Java 16 的新特性，降级到 JDK 8 或 Android 7.0 (API 24) 需要处理大量不兼容点。

以下是归纳整理的完整不兼容 API 清单及修改建议：

### 一、 集合框架不兼容 (影响范围最广)

| 不兼容 API | 引入版本 | 说明 | 替换方案 |
| :--- | :--- | :--- | :--- |
| `List.of()`, `Set.of()`, `Map.of()` | Java 9 | 约 35 个文件使用。 | `Collections.unmodifiableList(Arrays.asList(...))` |
| `List.copyOf()`, `Set.copyOf()` | Java 10 | 约 10 个文件使用。 | `new ArrayList<>(orig)` 并包装不可变。 |
| `Stream.toList()` | Java 16 | 约 15 个文件使用。 | `.collect(Collectors.toList())` |
| `Collectors.toUnmodifiableList()` | Java 10 | 1 个文件使用。 | `.collect(Collectors.collectingAndThen(...))` |

### 七、 注意事项
*   **Android 兼容性**: 如果目标是 Android 7.0 (API 24)，虽然它支持 Java 8 语法，但上述所有 Java 9+ 的 **API 调用** 依然是不兼容的，必须按上述方案替换。
*   **Unicode 风险**: `strip()` 替换为 `trim()` 时，如果字符串包含非 ASCII 的 Unicode 空白字符（如 `\u2000`），`trim()` 将无法识别，需确认业务场景。
*   **性能**: 手动替换 `readAllBytes()` 和 `readNBytes()` 时，建议使用缓冲区（如 8KB）以保持性能。

总计涉及约 **80 个源文件** 的修改。大部分修改（如 `List.of` 和 `.toList()`）可通过 IDE 全局正则替换快速完成。

## 总结

### 完全不支持的API（必须修改）
1. **符号链接**：`Files.createSymbolicLink()`, `Files.readSymbolicLink()`, `Files.isSymbolicLink()`, `Files.createLink()`
2. **POSIX属性**：`PosixFileAttributes`, `PosixFileAttributeView`, `PosixFilePermission`
3. **平台特定属性**：`Files.setAttribute("dos:hidden")`, `Files.getAttribute("unix:nlink")`, `Files.getAttribute("volume:vsn")`

### 可能不支持的API（需要测试和降级）
1. **原子移动**：`StandardCopyOption.ATOMIC_MOVE`, `AtomicMoveNotSupportedException`
2. **FileStore**：`Files.getFileStore()`, `FileStore.getAttribute()`
3. **LinkOption**：`LinkOption.NOFOLLOW_LINKS`（因为不支持符号链接）

### 完全支持的API（无需修改）
1. **基本文件属性**：`BasicFileAttributes`, `BasicFileAttributeView`
2. **目录遍历**：`DirectoryStream`, `Files.walk()`, `Files.list()`
3. **文件操作**：`Files.move()`, `Files.copy()`, `Files.delete()`, `Files.exists()`
4. **文件时间**：`FileTime`, `FileTime.toMillis()`, `FileTime.toInstant()`
5. **文件权限**：`File.setReadable()`, `File.setWritable()`, `File.setExecutable()`
6. **其他**：`StandardOpenOption`, `FileChannel.open()`, `PathMatcher`, `Files.createTempDirectory()`, `Files.write()`, `FileLock`

### 未使用的API（无需考虑）
- `WatchService`, `Path.register()`, `WatchKey`
- `DosFileAttributes`, `DosFileAttributeView`
- `UserDefinedFileAttributeView`
- `AclFileAttributeView`, `AclEntry`
- `Files.setOwner()`, `Files.getOwner()`, `UserPrincipal`
- `Path.toRealPath()`, `Path.normalize()`

总共需要修改约**15个文件**，主要集中在`FileUtils.java`、`FS_POSIX.java`、`FS.java`等核心文件系统工具类中。

## Path对象上Android 7.0不支持的方法详细说明

### 1. 符号链接相关方法（完全不支持）

**影响文件**：
- `org.eclipse.jgit/src/org/eclipse/jgit/util/FileUtils.java` (11处使用LinkOption.NOFOLLOW_LINKS) [18-cite-0](#18-cite-0) 
- `org.eclipse.jgit/src/org/eclipse/jgit/dircache/Checkout.java` (2处)
- `org.eclipse.jgit/src/org/eclipse/jgit/lib/FileModeCache.java` (1处)
- `org.eclipse.jgit/src/org/eclipse/jgit/util/FS_Win32.java` (1处)

**不支持的方法**：
```java
// Path对象本身的方法
Files.isSymbolicLink(Path path)  // Android不支持
Files.readSymbolicLink(Path path) // Android不支持
Files.createSymbolicLink(Path link, Path target) // Android不支持

// LinkOption参数
Files.exists(Path path, LinkOption.NOFOLLOW_LINKS)  // 虽然方法存在，但NOFOLLOW_LINKS无意义
Files.isDirectory(Path path, LinkOption.NOFOLLOW_LINKS) // 同上
Files.isRegularFile(Path path, LinkOption.NOFOLLOW_LINKS) // 同上
Files.readAttributes(Path path, BasicFileAttributes.class, LinkOption.NOFOLLOW_LINKS) // 同上
```

**项目中的具体使用**：
```java
// FileUtils.java 第463-465行
if (Files.exists(nioPath, LinkOption.NOFOLLOW_LINKS)) {
    BasicFileAttributes attrs = Files.readAttributes(nioPath,
            BasicFileAttributes.class, LinkOption.NOFOLLOW_LINKS);
    // ...
}

// FileUtils.java 第913-915行
if (Files.isSymbolicLink(nioPath))
    return Files.readSymbolicLink(nioPath).toString()
            .getBytes(UTF_8).length;
```

**影响**：
- Android不支持符号链接，这些方法会抛出`UnsupportedOperationException`或返回错误结果
- `LinkOption.NOFOLLOW_LINKS`在Android上无意义，因为根本没有符号链接

**替代方案**：
```java
// 移除LinkOption.NOFOLLOW_LINKS参数
Files.exists(nioPath)  // 而不是 Files.exists(nioPath, LinkOption.NOFOLLOW_LINKS)
Files.isDirectory(nioPath)  // 而不是 Files.isDirectory(nioPath, LinkOption.NOFOLLOW_LINKS)

// 对于符号链接检测，直接返回false
if (SystemReader.getInstance().isAndroid()) {
    return false; // Android不支持符号链接
}
```

```java
package org.eclipse.jgit.util;

import java.io.File;
import java.io.IOException;

/**
 * FS implementation for Android
 * Android不支持符号链接、硬链接、POSIX属性等高级文件系统功能
 *
 * @since 6.8
 */
public class FS_ANDROID extends FS_POSIX {
    
    /**
     * Constructor
     */
    public FS_ANDROID() {
        super();
    }
    
    /**
     * Constructor
     * @param src FS to copy some settings from
     */
    protected FS_ANDROID(FS src) {
        super(src);
    }
    
    @Override
    public FS newInstance() {
        return new FS_ANDROID(this);
    }
    
    @Override
    public boolean supportsSymlinks() {
        // Android不支持符号链接
        return false;
    }
    
    @Override
    public boolean supportsAtomicCreateNewFile() {
        // Android不支持原子文件创建
        return false;
    }
    
    @Override
    public LockToken createNewFileAtomic(File path) throws IOException {
        // 简化实现，不使用硬链接检测
        try {
            boolean created = path.createNewFile();
            return new LockToken(created, java.util.Optional.empty());
        } catch (IOException e) {
            return new LockToken(false, java.util.Optional.empty());
        }
    }
    
    @Override
    public boolean canExecute(File f) {
        // Android不支持POSIX权限，使用File.canExecute()
        if (!isFile(f)) {
            return false;
        }
        return f.canExecute();
    }
    
    @Override
    public boolean setExecute(File f, boolean canExecute) {
        // Android不支持POSIX权限，使用File.setExecutable()
        if (!isFile(f)) {
            return false;
        }
        return f.setExecutable(canExecute, false);
    }
    
    @Override
    public void setHidden(File path, boolean hidden) throws IOException {
        // Android不支持DOS隐藏属性，空操作
    }
    
    @Override
    public boolean isHidden(File f) throws IOException {
        // Android通过文件名判断隐藏（以.开头）
        return f.getName().startsWith(".");
    }
    
    @Override
    public Attributes getAttributes(File path) {
        // 使用基本属性而非POSIX属性
        return FileUtils.getFileAttributesBasic(this, path);
    }
}
```

面对这份庞大的降级清单，我的修正思路会遵循“先架构、后细节，先全局、后局部，先安全、后性能”的原则，避免陷入零散修改导致维护困难和回归风险。具体执行分为以下三个阶段：

---

### 第一阶段：架构适配——创建平台抽象层（解决约 50% 的文件系统问题）

**目标**：让所有通过 `FS` 实例派发的调用自动适配 Android，最小化散落的 `if/else` 修改。

**步骤**：
1. **新增 `FS_ANDROID` 类**，继承自 `FS_POSIX`，专门用于 Android 7.0+。
2. **在 `FSFactory.detect()` 中插入 Android 检测逻辑**，例如通过 `System.getProperty("java.vendor")` 或 JGit 已有的 `SystemReader.getInstance().isAndroid()` 返回 `FS_ANDROID` 实例。
3. **在 `FS_ANDROID` 中覆写以下方法**（直接利用清单二、三的结论）：
   - `supportsSymlinks()` → 返回 `false`（禁用所有符号链接路径）。
   - `createNewFileAtomic()` → 内部使用 `File.renameTo` 或者直接调用 `File.createNewFile()`，不依赖硬链接。
   - `getFileAttributesPosix(Path)` → 改为读取 `BasicFileAttributes`，权限相关方法返回保守值或抛出 `UnsupportedOperationException`。
   - `canExecute(Path)` / `setExecute(Path, boolean)` → 委托给 `File.canExecute()` / `File.setExecutable()`。
   - `setHidden(Path, boolean)` → 直接空操作（或通过文件名 `.` 判断，不抛异常）。
   - `isHidden(Path)` → 使用 `File.isHidden()` 或文件名检查。
   - 任何用到 `PosixFileAttributeView`、`LinkOption.NOFOLLOW_LINKS` 的 `FS` 内部工具方法 → 全部改写为兼容路径，避免 `NoSuchFileException` 或 `UnsupportedOperationException`。

**优势**：无需修改所有通过 `FS.getInstance()` 调用的业务代码，它们会自动使用 Android 安全实现。

---

### 第二阶段：API 降级——系统化替换 Java 9+ 特性（解决 80+ 文件的语法/API 问题）

**目标**：将代码从 Java 11 降到 Java 8 源码级别，同时保证所有第三方 API 调用在 Android 7.0 上存在。

**策略**：不是逐个文件手改，而是**组合使用 IDE 批量重构 + 自定义工具 + 编译约束**。

**具体动作**：

1. **编译环境先行**：
   - 修改 `pom.xml` 的 `java.version` 为 `1.8`，设置 `source/target` 为 `8`，并引入 `animal-sniffer-maven-plugin`，使用 Android 24 的签名文件作为 API 检查边界。这样任何误用的高版本 API 都会在编译期被拦截，而不是运行时崩溃。
   - Eclipse 配置同步更新为 `JavaSE-1.8`，确保 IDE 实时提示错误。

2. **集合工厂方法替换**（`List.of`、`Set.of`、`Map.of`、`copyOf` 等，约 45 处）：
   - 编写一个简单的 **IntelliJ/IDEA 结构化搜索模板** 或 Eclipse 正则，将 `List.of(a, b, ...)` 替换为 `Collections.unmodifiableList(Arrays.asList(a, b, ...))`。
   - 对于 `List.copyOf`，可全局替换为 `Collections.unmodifiableList(new ArrayList<>(orig))`，注意保留不可变性语义。
   - `Stream.toList()`（16 处）统一替换为 `.collect(Collectors.toList())`。
   - 这些替换纯机械，可在一小时内完成。

3. **字符串 API 替换**（`strip`、`lines`、`repeat` 等，较少）：
   - `strip()` → `trim()`，并添加注释警告 Unicode 空白差异。
   - `stripTrailing()` → 复用项目已有的 `Strings.stripTrailingWhitespace`。
   - `lines()` → 封装一个工具方法，内部优先使用 `BufferedReader.lines()` 或手动 `split("\\R")`，保证跨平台换行处理。
   - 同时全局搜索 `repeat(` 调用，确认是否误引入，若有则替换为循环拼接。

4. **IO / 流 API 替换**（`readAllBytes`、`readNBytes`、`transferTo` 等，约 10 处）：
   - **统一封装成 JGit 内部工具方法**，例如 `IOUtils.readAllBytes(InputStream)`，内部使用 8KB 缓冲区循环读入 `ByteArrayOutputStream`。
   - 在 `ByteBufferInputStream` 等底层类中将 `readNBytes` 调用替换为循环 `read(byte[], off, len)`，确保语义完全一致（读满指定长度）。
   - `transferTo` 同样封装为 `IOUtils.copy(InputStream, OutputStream)`，替换所有调用点。
   - 这样修改后，任何未来新增的 IO 代码也可复用该安全实现。

5. **其他 API 替换**（`Optional.or`、`Objects.checkFromIndexSize` 等）：
   - `Optional.or` → 封装一个静态辅助方法 `Optional.or(opt, supplier)`，实现“存在即返回，否则调用 supplier”，全局替换。
   - `Objects.checkFromIndexSize` → 手动实现边界检查，逻辑简单且清晰。
   - `Predicate.not()` → 全局搜索，内联为 lambda `x -> !pred.test(x)`。
   - `toArray(T[]::new)` → 替换为 `toArray(new T[0])`，性能在 Java 8 上依然优异。

**工具建议**：使用 `Intellij IDEA` 的 “Structural Replace” 或 `Eclipse` 的 “Clean Up” 配合自定义规则，可以完成 90% 的机械替换。剩余需要人工阅读确认的地方（如 `strip` 的 Unicode 行为）再逐个标记 TODO。

### 第三阶段：文件系统兼容性精准狙击——处理静态工具方法（15 个文件）

经过第一阶段，所有走 `FS` 实例的路径已经安全，剩余的是 `FileUtils`、`Checkout` 等**静态工具方法**，它们直接调用 `java.nio.file.Files` 的高版本或 Android 不支持的静态 API。这些地方需要手动逐一修改，但数量可控。

**执行清单**：

1. **`FileUtils.java`（修改量最大，约 20 处）**：
   - **符号链接相关（5 处）**：用 `try-catch` 包裹 `Files.isSymbolicLink` 并返回 `false`，或在方法开头检测 Android 直接返回保守值。
   - **`LinkOption.NOFOLLOW_LINKS` 参数（11 处）**：由于 Android 无符号链接，移除该参数完全等价。可封装一个内部方法 `linkOptionForAndroid()`，根据 `SystemReader.isAndroid()` 返回空数组或含 `NOFOLLOW_LINKS` 的数组，但更简单的做法是直接删除该参数。
   - **DOS 隐藏属性（1 处）**：`setAttribute("dos:hidden")` 直接抛出 `UnsupportedOperationException` 或记录日志后忽略，Android 不依赖此文件属性。
   - **POSIX 属性读取（4 处）**：如 `getFileAttributesPosix`，改用 `BasicFileAttributes` 读取大小、时间等，权限部分返回保守值（如假设文件不可执行则调用 `File.canExecute()`）。
2. **`Checkout.java`、`FileModeCache.java` 中的 LinkOption 使用（3 处）**：同样移除 `NOFOLLOW_LINKS` 参数，保持一致性。
3. **`FS_POSIX.java` 中的静态直接调用（2 处）**：如硬链接创建和 `unix:nlink` 属性读取，改为在 `FS_ANDROID` 覆写相关方法后，这些调用不应再发生；但如果是静态工具代码，需要添加 `isAndroid()` 判断。
4. **原子移动降级（11 个文件）**：Android 上的 `File.renameTo` 本身就不是原子的，建议项目内统一捕获 `AtomicMoveNotSupportedException` 并降级为普通移动。可以在 `FileUtils.rename()` 工具方法中实现统一降级逻辑，其余 11 个文件调用该工具方法即可。

**最终验证**：
- 使用 `animal-sniffer-maven-plugin` 或 `japicmp` 对比编译后的 class 文件，确保零引用高版本 API。
- 在 Android 7.0 模拟器或真机上运行 JGit 的所有单元测试（尤其是文件 I/O 和符号链接相关测试），确保通过率不低于标准 JVM。

### 关键原则总结

- **封装工具方法优先**：不要到处散落 if/else，而是将兼容性差异封装进 `IOUtils`、`CollectionCompat`、`FileCompat` 等内部类，业务代码零感知。
- **编译期约束代替 Code Review**：利用 Maven 插件和 IDE 配置，让机器拦截不兼容调用，避免人工遗漏。
- **分阶段提交**：每个阶段完成后跑一次全量测试，确保增量修改不会引入回归。
- **性能不妥协**：所有手写的 IO 替换使用 8KB 缓冲区，循环逻辑注意对象分配开销，尽量接近原 API 实现效率。

按照上述方案，总工作量可估为 **2～3 人天**，且修改过程系统化、可追溯、可自动化验证，远比零散替换稳健。
